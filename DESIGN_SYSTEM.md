# SMY Design System

Status: **D1 specification — Implemented, checked in CI (Phase 6).** Icons
follow in Phase 12 (D2), component specifications in Phase 17 (D3). Binding
requirements: `docs/DESIGN_PROMPT.md`; brand identity:
`docs/BRAND_PROMPT.md`, `design/brand/BRAND_GUIDELINES.md`.

Reference sheet (generated, CI artefact): `build/brand/themes-preview.png`
(`make brand`). It shows the three themes on a sample settings window. It is
a review aid for tokens, **not** a component design.

## 1. Concept: "Module"

The interface language grows from the logo (ADR 0011): a calm, rounded
**frame** that holds content, and one bright **core** that marks what
matters. Surfaces are quiet, nearly flat layers of the brand's dark blues
(or light greys); the cyan accent appears in few, meaningful places —
the primary action, the current selection, keyboard focus, progress.
Geometry is precise and soft: 8 px corners on controls, 12–16 px on panels
and windows, like the logo's frame and core.

It deliberately avoids the signature looks of other systems: no translucent
blurred glass, no coloured traffic-light window buttons, no tiles, no
skeuomorphic depth.

## 2. Principles

| # | Principle | Do | Don't |
|---|---|---|---|
| 1 | **Frame and core.** Structure is quiet; one element per view carries the accent. | One accent-filled primary button per dialog; the rest are outlined. | Several cyan buttons, badges and icons competing in one view. |
| 2 | **Colour means something.** The accent signals action, selection, focus or progress; red/amber/green/blue only signal status. | A green dot plus the text "Installed". | Colour as decoration, or colour as the *only* carrier of meaning. |
| 3 | **Contrast is measured, not guessed.** Every text and boundary pair is in `themes.json` and tested. | Add the new pair to `pairs` before using it. | Grey-on-grey text "because it looks elegant"; text over images without a plate. |
| 4 | **Calm motion.** Short, purposeful transitions; none when "reduce motion" is on. | 160 ms fade + 8 px slide when a panel opens. | Bounces, parallax, looping or attention-seeking animation. |
| 5 | **Software-first rendering.** Everything must draw at 60 Hz on the boot framebuffer without a GPU. | Solid fills, a 1 px border, at most one small shadow. | Background blur, stacked shadows, large gradients, noise textures. |
| 6 | **Readable in our languages.** Uzbek Latin and Cyrillic are first-class; text scales. | Test strings with `Oʻ gʻ` (U+02BB) and `Ўў Ққ Ғғ Ҳҳ`; minimum 12 px. | An apostrophe `'` instead of `ʻ`; clipped or truncated labels. |
| 7 | **Keyboard is first-class.** Focus is always visible. | A 2 px focus ring with 2 px offset (3 px in high contrast). | Removing the focus outline; focus that only changes colour slightly. |

## 3. Colour system

### 3.1 Layers

1. **Brand palette** — `design/tokens/brand-colors.json` (owner-provided,
   Phase 5B).
2. **Base ramps** — `design/tokens/color-base.json`, generated by
   `tools/design/gen_palette.py` from `palette-anchors.json`. Seven hues
   (neutral, cyan, violet, green, amber, red, blue), 16 steps each:
   0, 50, 100, 150, 200, 300 … 700, **750**, 800, 850, 900, 950, 1000
   (0 lightest). Anchor steps keep exact colours (all brand colours are
   anchors); the rest are interpolated in OKLCH and gamut-mapped by lowering
   chroma. Lightness falls strictly along each ramp (checked).
3. **Semantic tokens per theme** — `design/tokens/themes.json`. Components use
   only these names (`surface`, `text-primary`, `accent`, `danger`, …), never
   ramp steps or hex values.

### 3.2 Semantic tokens

| Token | Use |
|---|---|
| `bg-app` | desktop / application background |
| `surface` | windows, cards, main content |
| `surface-raised` | menus, popovers, dialogs (above `surface`) |
| `surface-sunken` | inputs, wells, sidebars |
| `surface-hover` | hover fill of rows and quiet buttons |
| `border-subtle` | dividers (decoration only) |
| `border-strong` | control boundaries (≥ 3:1) |
| `text-primary`, `text-secondary`, `text-disabled` | text levels |
| `text-on-accent` | text on accent fills |
| `accent`, `accent-hover`, `accent-pressed` | primary action, links, progress |
| `accent-subtle` | selected row / item background |
| `focus-ring` | keyboard focus indicator |
| `success`, `warning`, `danger`, `info` | status text and icons |
| `*-surface` | tinted backgrounds of status banners |

### 3.3 Themes

| | Dark (default) | Light | High contrast |
|---|---|---|---|
| Background | `#080B12` void | `#F5F7FB` | `#080B12` void |
| Surface | `#101522` deep | `#FFFFFF` | `#080B12` + 2 px `border-strong` |
| Text | `#F4F7FF` | `#141A29` | `#FFFFFF` |
| Accent | `#54F6E8` cyan | **`#077479`** (proposal, §3.5) | `#54F6E8` |
| Focus ring | cyan | `#077479` | `#FFD166` amber, 3 px |
| Minimums | text 4.5:1, large/UI 3:1 | same | text **7:1**, large/UI 4.5:1 |

High contrast also replaces shadows with borders, uses 2 px borders on
windows and controls, and outlines status banners in their status colour.

### 3.4 Contrast test

`tools/design/check_contrast.py` (CI: `make design-check`) checks **147
pairs** in the three themes. Each pair is one foreground token on one
background token, from the `pairs` list in `themes.json`, and must meet the
theme's minimum for its kind (text / UI). Lowest measured values:
- light `border-strong` on `surface-sunken`: 3.42:1 (minimum 3);
- dark `text-secondary` on `surface-hover`: 4.59:1 (minimum 4.5).

Exempt tokens have their own documented floors: `text-disabled` must reach
at least 2:1 (WCAG exempts inactive components), and `border-subtle` at
least 1.15:1 (decoration only). The test fails if a theme misses a token, or
if a token is not a base or brand colour.

### 3.5 Decisions on the Phase 5B open points

- **Light accent.** `#087F83` is 4.48:1 on `#F5F7FB`, which fails 4.5:1 for
  text. Proposal: the light theme's `accent` (buttons, links, focus) uses
  **`#077479`** (cyan.750: 5.18:1 on `#F5F7FB`, 5.55:1 on white). The logo
  keeps `#087F83` for its core: that core is a graphic, where 3:1 applies.
  **Owner approval requested.**
- **Light-theme status colours** (new, were missing): success `#0E7044`,
  warning `#8A5000`, danger `#B8243D`, info `#155FA8`. Each is ≥ 5:1 on
  `#F5F7FB` and ≥ 4.5:1 on its tinted banner. These are the step-700
  anchors of their ramps. **Owner approval requested.**
- **High-contrast theme** (new): built from the same ramps; amber focus
  ring so focus never looks like selection.

## 4. Foundations (`design/tokens/foundations.json`)

All lengths are logical pixels at 1×. Display scale factors are 1×, 1.25×,
1.5× and 2×; the toolkit scales and snaps to whole device pixels.

- **Type.** UI: Inter. Mono: IBM Plex Mono. Scale (size/line): caption
  12/16, body-small 13/18, body 14/20, label 13/16 medium, title-small
  16/22, title 20/28, title-large 24/32, display 32/40, mono 13/20. The
  minimum text size is 12 px. Line height is at least 1.2× the size and
  always even. Large sizes get slightly negative tracking. Weights:
  400/500/600/700.
- **Space.** A 4 px grid: 0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, plus 2 px
  for optical nudges only.
- **Size.** Control heights are 24, 32 (default) and 40. Icons are 16, 20 and
  24. The title bar is 40. The minimum target is 24 × 24 (WCAG 2.2 2.5.8).
- **Radius.** 0 / 4 / 8 (controls) / 12 (panels) / 16 (windows) / full.
- **Border.** Hairline 1, strong 2. The focus ring is 2 px with a 2 px offset
  (3 px in high contrast).
- **Elevation.** Levels 0–3, each with **one** shadow and a small blur
  (≤ 16 px), so it can be drawn in software. High contrast uses outlines
  instead.
- **Motion.** Durations: 0 / 100 / 160 / 240 / 320 ms. Easings: standard,
  enter and exit (cubic-bezier). With reduced motion, every duration
  becomes 0; opacity fades use the 100 ms duration.
- **States.** These are layers over a component's fill: hover 8 %, pressed
  14 %, selected 16 % (accent). Disabled is 40 % opacity. The modal scrim
  is 56 %.

The generator rejects:
- spacing off the 4 px grid;
- text below 12 px;
- a line height below 1.2× the size, or an odd one;
- an unknown font weight;
- a radius scale that is not increasing;
- a touch target below 24 px.

## 5. Tokens and generated code

The source of truth is `design/tokens/*.json`. `tools/design/gen_tokens.py`
generates two files into `build/generated/design/`:
- `smy_tokens.h`: about 300 `#define`s. Colours are `0xAARRGGBB`; sizes are
  integers; alphas are 0–255; easing values are in thousandths. It needs no
  floating point.
- `smy_tokens.css`: custom properties. `data-theme` selects the theme;
  dark is the default. It honours `prefers-reduced-motion`.

**Decision: generated files are not committed** (ADR 0013). They are
build products, like the ISO. CI regenerates them on every run, compiles
the header with all warnings as errors, and uploads both as artefacts. Base
ramps (`color-base.json`) are the one generated file kept in git, so
reviewers can read the colours; `gen_palette.py --check` keeps it
identical to its source.

## 6. Typography and font licences

| Font | Version | Licence | Use | Coverage check |
|---|---|---|---|---|
| Inter | 4.1 (rsms/inter release) | SIL OFL 1.1 | UI | ✓ 183/183 required characters |
| IBM Plex Mono | 2.5.0 (IBM/plex release) | SIL OFL 1.1, Reserved Font Name "Plex" | terminal, code | ✓ 183/183 |

- Fetched by `tools/fetch-fonts.sh` from the projects' own releases and
  pinned by SHA-256. They are not committed. They are only shipped in the ISO
  once the desktop exists (Phase 20).
- `tools/design/check_font_coverage.py` reads each font's `cmap`. It
  requires:
  - printable ASCII;
  - Uzbek Latin `Oʻ oʻ Gʻ gʻ` (U+02BB) and `’`;
  - the Russian Cyrillic alphabet plus `Ўў Ққ Ғғ Ҳҳ`;
  - UI punctuation (`« » – — … • € № ©`).

  As a negative check, IPAGothic fails it: 9 characters are missing,
  including U+02BB and all Uzbek Cyrillic letters.
- The OFL allows bundling and redistribution. Fonts may not be sold on
  their own. A *modified* Plex (for example a subset) must not be called
  "Plex". SMY-OS never calls these fonts SMY typefaces.
- The kernel's early text console keeps its own bitmap font (later phase).
  It never uses these TTFs.

## 7. Performance rules (`DESIGN_PROMPT.md` §9)

- Every effect must render in the software renderer on the boot
  framebuffer at 60 Hz. The budget is a full-screen redraw of 1920 × 1080 in
  well under 16 ms on one core.
- Allowed: solid fills, 1–2 px borders, rounded rectangles, one shadow per
  elevation level, and opacity fades.
- Blur is **off by default**. If a GPU path ever adds it, it stays optional.
  No full-screen effects run on idle frames.
- Animations stop when nothing changes; "reduce motion" removes movement.

## 8. Separation (`DESIGN_PROMPT.md` §10)

All visual components run in user space (toolkit Phase 19, desktop
Phase 20+). They are separate from the kernel and from privileged
services. The design library (`design/`, generated tokens) contains no
kernel code. The kernel uses only the boot logo pixels (Phase 5B) and its
own console font.

## 9. Rationale

- **Why dark first.** The brand palette is dark ("void"), and the boot
  screen, installer and first impression are dark. Light and high contrast
  are complete themes, not afterthoughts. Each has the same token set,
  which is checked.
- **Why OKLCH ramps.** Interpolating in OKLCH gives perceptually even steps
  and stable hue. sRGB interpolation turns muddy in the middle.
- **Why the 750 step.** It lets the owner-provided `#087F83` (700) stay
  unchanged, while giving text a compliant neighbour.
- **Why amber focus in high contrast.** Cyan already marks selection there.
  A different hue keeps focus and selection apart for people who rely on
  the high-contrast theme.
